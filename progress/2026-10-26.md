# FlowMind AI — Progress 2026-10-26

## Code Runner hardening (supersedes closed PR #2)

- `ENABLE_CODE_NODE` (default `false`) gates the in-process Code Runner.
- When disabled, the node is **skipped** (input passed through, `skipped: true` + warning in the trace) instead of returning `error`, which used to halt the whole workflow.
- Startup logs which saved workflows contain a Code Runner node; `.env.example` documents the flag and upgrade note.
- `GET /config/features` exposes the flag; the node palette hides Code Runner when it is off.

## Inactive-account handling
- Inactive users now get **403** "Account not yet activated" instead of a generic 401 (which also wiped their session).
- Login and `/auth/me` work for inactive users so the Pending Approval screen is actually reachable; all other endpoints require an active account.

## Tests
- `backend/tests` + `pytest.ini` (`pythonpath = .`): flag default, skip behaviour, workflow not halting, enabled path, 403 for inactive users. Run `pytest` from `backend/`.

## Security audit remediation (all 8 findings)
See `docs/SECURITY_AUDIT.md` for the per-finding status. Highlights: SSRF guard, credit reservation + atomic settlement, encrypted provider keys / node-secret vault / hashed API tokens, redacted persisted traces + retention, DB session released during runs, auth rate limits + JWT expiry, fail-closed verification/decision nodes, killable subprocess Code Runner.

Upgrade notes: existing users' API tokens are hashed on first start — they must use **Regenerate** in the Live API panel to see a token again (old tokens keep working). Back up `SECRET_KEY`/`ENCRYPTION_KEY`: losing it makes stored secrets unreadable. Passwords now require 8+ chars at signup.
